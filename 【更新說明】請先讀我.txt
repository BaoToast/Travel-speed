■ v2.20.7：Manager 比較的方向名稱不會再一半新一半舊（使用者回報）

  使用者回報：Manager 比較裡，同一個計畫有些路段顯示改好的方向名稱
  （南-北(北上)），有些還是「方向1／方向2」。

  成因：判斷「這個路段有沒有取過名字」時，只看「roadMeta 有沒有這筆項目」，
  沒有看「項目裡的名字是不是還是預設值」。而**設定路段有效期間時就會建立
  一筆項目**，內容是 {directionA:"方向1", directionB:"方向2", 起訖季度}
  ——那筆項目「有值」，於是擋掉了本機同一個計畫真正取好的名稱。
  所以是逐路段的：哪些路段設過有效期間，哪些就顯示不出來。

  改法：新增 hasRealDirectionName()，把「有沒有這筆項目」和「有沒有取過名字」
  分開；managerDirectionName() 改為「專案包 → 本機 → 鍵值」，挑真的有名字的那一份。

  ★ 使用者不需要重新匯出專案包，本版直接讀本機的設定。
  ★ 已實測：把本版的守門檢查放到 v2.20.6 的原始碼上會紅字，
     輸出 `示範路B(起~迄)|方向1|方向1`，與使用者截圖的症狀一致。

■ v2.20.6：方向顯示名稱全站同步

  使用者在「路段管理」替方向1／方向2設定顯示名稱後，尖峰明細、
  尖峰彙總、路段速限、結論草稿、報告文字草稿、健康檢查、CSV 匯出
  與 Manager 比較現在都會使用同一組顯示名稱。

  方向的內部鍵值仍是「方向1／方向2」，沒有改寫既有資料；速限設定、
  已儲存的結論篩選條件、舊版備份與專案包都能繼續使用。
  Manager 專案包補上 roadMeta，跨計畫比較也能帶入各路段方向名稱。

  本版新增方向名稱端對端測試及原始碼守門檢查。完整驗證結果為：
  單元測試 54/54、版本一致性檢查 18/18、瀏覽器操作測試 4 支全過，
  並確認舊版 .xls、.xlsx、代表紀錄及同筆總延滯計算均未發生迴歸。

  完整專案新增 .gitattributes，避免 Windows 取出原始碼時自動改寫
  換行字元；本專案仍只發布 GitHub Pages，不使用 GPT Site，
  也不需要或包含 .openai/hosting.json。

■ v2.20.4：手冊的版號與日期改為單一來源

  v2.20.3 的手冊封面戳記寫 2026-08-25、每一頁頁尾卻印 2026-08-24。
  內容都對，只是兩處日期不一致。

  成因：兩支手冊產生程式各自把版號與日期**寫死**，升版時以字串取代
  修改，只要有一處對不上就安靜地失敗——而日期沒有任何檢查在看，
  版號檢查照樣全綠。同一種錯誤在這一組系統已經犯過四次
  （姊妹系統連續三版的更新說明也是這樣完全沒進到手冊裡）。

  根治：新增 manual-src/release.mjs，頁尾字樣與手冊檔名都由
  manual.html 封面戳記推導，兩者結構上不可能不一致。
  check-version.mjs 由 14 項增為 18 項，新增：找得到封面戳記、
  戳記版號等於 app.js 的版號、兩支產生程式裡沒有寫死的版號或日期。

  **已實測新檢查會失敗**：把寫死的日期塞回 build-pdf.mjs → 該項紅字；
  把封面戳記改成 v2.20.9 → 版號比對項紅字；還原後全部通過。
  （只加會通過的檢查等於沒加檢查。）

  網站本體只改版號字樣，app.js 的計算、門檻與畫面完全沒動。

■ v2.20.3：結論草稿的「條件範本」會跟著專案包走了

  範本只存在當下那一台電腦的瀏覽器裡，而「下載專案包」與
  「個人全部計畫包」都沒有把它收進去——在 A 電腦存了好幾組常用條件，
  帶到 B 電腦匯入之後一組都不會出現，畫面卻只說匯入成功。
  本版把 conclusionTemplates 一併收進兩種包，匯入時還原回去。

  只有備份檔實際帶著這個欄位時才覆蓋該計畫的範本；
  匯入舊版專案包不會把本機既有的範本清掉。
  升版前下載的舊包裡本來就沒有範本，請使用者重新下載一份。

  新增 backup-completeness.test.mjs（4 項）。

■ v2.20.2：Excel 解析多了一道邊界檢查

  本系統的 SheetJS 已經是官方 0.20.3（安全警示的修正版），
  這一版再加一層：解析時關掉用不到的公式、內嵌 HTML 與巨集；
  解析前後比對瀏覽器的內建物件，一旦某個檔案真的動到它，
  就當場中止這次匯入並指出是哪一個檔案，而不是安靜地繼續。
  即使日後元件版本被換回舊版，也不會無聲通過。

■ v2.20.2：備份包在 Windows 上更容易自行驗證

  測試用的瀏覽器尋找順序補上 Windows 的 Chrome 與 Edge、
  以及 macOS 與 Linux 的常見安裝位置——多數人是在自己的 Windows 電腦
  打開這個備份包，本機已經有瀏覽器時就不必再另外下載一份。


如何更新
-----------------------------------------------------------------
把本壓縮檔內的所有檔案，覆蓋到 GitHub repository
（https://github.com/baotoast/Travel-speed）的根目錄，然後 commit + push。
GitHub Pages 會自動重新發布，約 1～3 分鐘。

**請先手動刪除舊版檔案**（檔名帶版號，上傳不會自動刪掉舊的）：
  manuals 資料夾裡所有不是 v2.20.8 的
  交通服務水準分析系統_新手使用手冊_*.pdf 與 .docx；
  根目錄所有舊版 VALIDATION_v*.md，只保留 VALIDATION_v2.20.8.md；
  根目錄不可有過時的「給Claude的交接說明_v2.20.1.md」。

部署完成後請確認：左上角顯示「正式版 v2.20.8」，
「新手說明」頁的兩個下載連結點得下去（不是 404）。
