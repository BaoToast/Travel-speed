■ v2.20.35：拖曳上傳，以及判讀大量檔案時的進度提示（不動計算）

  【一】現在可以用拖的把檔案丟進來

    三個地方都收拖曳，拖曳經過時該區塊會亮起來：
      ・尖峰批次匯入（.xls／.xlsx／.xlsm，可一次拖多份）
      ・備份與淨空 → 選取或拖曳備份檔（.json）
      ・Manager 匯入 Project 專案包（.json，可一次拖多份）

    拖到不是指定副檔名的檔案會被擋下來，而且會講出來，
    不會安靜地少匯入幾個檔。

  【二】檔案掉在放置區外面，不會再把您帶離頁面

    以前檔案不小心掉在旁邊時，瀏覽器會直接開啟那個檔案，等於離開系統畫面。
    現在會擋住，游標也會顯示「不可放置」。

  【三】判讀大量檔案時看得到進度

    使用者回報「上傳了大量的檔案後，因為沒有『讀取中』等提示文字，
    會誤以為沒上傳成功」。

    實測過原因：程式其實有反應，24 份 64KB 的檔案要 5.7 秒，這段期間
    右邊「辨識預覽」的小字確實顯示著「讀取中…」、畫面也沒卡死。
    問題是那行字在畫面另一側、很小、而且一動也不動，按鈕本身文字
    又完全沒變，看起來跟當掉一樣。

    現在按鈕本身會變成「讀取中… 3／18」，檔案資訊列同步寫出正在讀
    哪一個檔名。看到數字在跳就是還在跑，不必重按。

  **只動上傳與判讀的操作回饋，旅行速率、行駛速率、延滯、LOS 門檻與
    代表紀錄選取順序一行都沒有動。**


■ v2.20.34：修好一支擋不住東西的守門測試（不動程式、不動計算）

  e2e-reveal.mjs 有一項「結果已經看得到時，畫面不可以跳」，是把畫面捲到
  整頁最底下之後量的。那個位置本來就到了捲動極限、畫面根本動不了，
  所以不管程式怎麼寫都會通過——實測把 revealResult() 改成無條件捲動，
  這一項仍然是綠的，等於當時擋不住任何東西。

  現在改成：先在頁尾補一塊空白，讓「草稿框整個看得見」與「畫面還捲得動」
  同時成立，再把草稿框放到視窗中間；並直接在頁面裡對按鈕發 click，
  不借用 Playwright 按之前的自動捲動。前置條件本身也列成一項檢查，
  否則版面一改，這一項又會悄悄變回恆真。對無條件捲動的版本實測紅字。

  **只動測試腳本與版號，程式行為與計算完全沒有變更。**


■ v2.20.33：全文搜尋不再誤清除表頭欄位篩選（不動計算）

  v2.20.32 新增的 Excel 式表頭篩選有一個狀態邊界：先勾選 A 路段，
  再於全文搜尋輸入 B 路段時，畫面應暫時顯示 0 筆，但程式會把 A 路段
  誤判成「資料已刪除」而清掉。清空搜尋後就失去原本條件。

  現在搜尋結果只用來限制畫面與下拉選項；判斷既有條件是否真的失效時，
  會改看目前計畫的完整資料母體。清空搜尋後，原本的欄位條件會正確恢復。
  尖峰明細、尖峰彙總與 Manager 比較三處共用同一套修正，並新增瀏覽器回歸案例。

■ v2.20.32：表頭欄位篩選，以及按下按鈕之後看得到結果（都不動計算）

  【一】尖峰明細、尖峰彙總、Manager 比較改成像 Excel 的資料篩選

    使用者的要求：「針對表標題列提供篩選，例如期間篩選 115Q2，然後路段
    篩選 A 路段，表單就呈現出 115Q2 A 路段的資訊。」

    ・選項清單依「其他欄位目前的條件」算出來，不會出現勾了卻沒資料的選項；
      但打開自己這一欄時清單仍是完整的，隨時改得掉。
    ・篩選比對的是**儲存的民國年**，切換民國／西元顯示不會弄丟已勾的條件。

  【二】按下按鈕之後，結果若在畫面外會把您帶過去

    使用者回報：「路段管理的功能頁面中，修改正式名稱／合併重複路段，
    按下預覽修改影響／顯示合併影響後，因為畫面停在原地，所以使用者不知道
    預覽畫面已經顯示在下方了，會誤以為程式沒任何反應。」

    實測（視窗高 900px）：預覽面板頂端在 1243px、健康檢查結果在 1865px、
    結論草稿在 1331px——都在畫面外。現在會捲過去，
    但**只在結果看不到時才捲**；本來就看得到（例如已經滑到底再按）完全不動。

  【三】結論草稿只留一顆產生鈕

    原本頁首與草稿框旁各有一顆，呼叫同一個函式。實際動線用不到頁首那顆
    ——條件、條件範本、草稿框都在下方。已移除頁首那顆，下方那顆改名
    「產生草稿」。

  【一】超出可換算範圍的年份會被擋下

    現在改走三支共用的把關，訊息與匯入流程完全同一句。

  【二】填西元年會換算成民國年再存

    全系統其他地方一律存民國年，只有這裡是例外；而且那個值直接回填輸入框
    顯示，不會跟著「年份顯示」切換走。現在會換算並在提示裡說明存成什麼。

  【三】打錯字不會再讓路段悄悄消失（本版最要緊的一項）

    開始季度少按一個鍵打成 9999Q1，該路段在所有真的有資料的季度都會被判成

    現在不可用的界線會退化成「沒有設定」，路段仍然看得見。
    看不見的錯誤比看得見的危險得多。

  【四】既有資料的西元寫法會在載入時統一成民國年

    2026Q1 → 115Q1。兩種寫法的排序鍵本來就相同，這只是換寫法、指的是
    同一季，不會改變任何一筆速限、旅行速率或服務水準。
    認不出來的值原樣留著，不擅自丟掉您的資料。

  【五】季度輸入的判定改看年份數值，並與另外兩支系統對齊

    以前四碼一律當西元，所以民國 115 打成 0115Q1 會被退回並說「民國年
    請填 90～200」——但 0115 就是 115。現在會正確存成 115Q1。全形數字、

■ v2.20.23：期別可以填民國年或西元年，畫面與匯出可以切換兩種寫法

  【一】匯入時的調查年度，民國與西元都收得進去

    舊版只收民國年（90～200），拿到以西元年標示的委託案時只能自己換算。
    本版兩種都收：填 2026，輸入框下方會即時顯示「將存成 115」。

    但**資料一律以民國年記錄**。這是必要的——如果照您打的字原樣存，
    同一季會因為寫法不同而變成兩個分開的期別，歷季比較被拆成兩段而且
    永遠不會合併；更麻煩的是它們的排序位置完全相同，畫面上看起來只像
    「同一期出現了兩次」，很難想到是寫法造成的。

  【二】頁首多了一顆「年份顯示」按鈕

    按一下在民國年（115Q1）與西元年（2026Q1）之間切換。畫面上的表格、
    圖表、下拉選單、結論草稿、報告文字草稿，以及匯出的 Excel（含圖表的
    類別軸）、CSV 與成果包裡的文字檔，全部跟著同一個設定走——不會出現
    畫面寫 2026Q1、交出去的報表卻寫 115Q1 的情形。

  【這顆按鈕只換看到的字，不動任何一個數字】

    分組、排序、識別鍵、期別篩選與所有計算，全部走儲存的那個值；
    切換年份寫法不會挑到不同的資料，也不會讓任何數字改變一位。
    下拉選單的「值」也仍然是民國年，只有顯示的文字換掉——這一點很重要，
    否則切成西元年之後，成果交付範圍與結論草稿的單季條件會挑不到資料。

    端對端測試會在切換前後把整張尖峰明細表逐字比對一次：除了期別那一欄，
    每一格數字都必須完全相同；並且確認匯出的 Excel 儲存格與圖表類別軸
    寫的是同一個期別、列的順序沒有被顯示切換打亂。

  【兩個顯示開關可以各自獨立使用】

    ・期別顯示：季別（115Q1）⇄ 實際調查月份（115年2、3月）
    ・年份顯示：民國年（115Q1）⇄ 西元年（2026Q1）
    兩個一起開就是「2026年2、3月」。

  【有三處刻意維持民國年，不跟著切換】

    ・匯入預覽與期別確認視窗裡的期別字樣——它們講的是「會存成什麼」。
    ・備份、Project 專案包與成果包內的 JSON 資料檔（會被再匯入的）。
    ・成果交付草稿的內部儲存鍵（跟著換的話，之前存的草稿會找不到）。

  【三】期別排序鍵認得四碼西元年

    備份還原、手動編輯過的資料與外部匯入都可能帶進四碼寫法。
    舊版只認 2～3 碼，四碼回 -1 會整段排到最前面。

■ v2.20.22：三支系統跨系統徹查後的四項修正

  本版是「交通服務水準、路口轉向、全日交通量」三支一次跨系統徹查的結果。
  作法是拿 37 份真實調查表分別餵給不同系統、比對彼此的判讀與數字，
  凡是不一致的就往下追。

  【一】合併路段時不再蓋掉目標路段既有的速限（會影響服務水準判定）

    把 A 路段合併進 B 路段時，舊版會把 A 的速限版本無條件併入 B。
    若兩者的有效期間重疊，B 原本就有、而且不在這次合併範圍內的紀錄
    會跟著換速限——實測一筆紀錄的速限由 40 變成 70、速限比 0.8250
    變成 0.4714、服務水準由 A 級變成 D 級，而確認視窗只統計 A 路段的
    筆數，完全不會提到這件事。

    本版改為保留目標路段既有的版本，只帶進有效期間完全不重疊的，
    被略過的版本會列在完成訊息裡，需要改用來源路段的速限時請自行新增版本。

  【二】路段名稱只差一個分隔符時，不再被當成兩條不同的路段

    「鳳北路(南星路～沿海四路)」與「鳳北路(南星路-沿海四路)」是同一條路。
    舊版的重複路段偵測漏掉了半形連字號，於是這種配對永遠算不出相同的
    簽章，而「名稱疑似重複」的提醒也始終不會出現。實測您提供的
    14013TS601 平日與假日兩份檔案就是差這一個字元，結果被記成兩條路段、
    平假日比較整個不成立。

  【三】同一份檔案有兩個不同的調查日期時會指出來

    實測 11535TS1501／1502／1503 三份檔案，上午尖峰的表頭寫 115Q1、
    下午尖峰卻還留著上一季的 114Q4（套模板時忘了改一處）。舊版只看
    第一個有標示的日期，於是對一份自己前後矛盾的檔案回報「相符」。

■ v2.20.14-1：調查日期與季度對不對得起來

  選錯季度是最容易發生、也最難事後發現的一種錯——資料本身完全正常，
  只是被掛到錯的一季，之後的趨勢圖與歷季比較就整個歪掉。

  匯入前輸入的季度（例如 115Q1）與檔案表頭寫的調查日期如果對不起來，
  預覽上方會用**紅底**標出是哪幾份、檔案裡寫的是哪一天、屬於哪一季、
  來源是哪個工作表哪一格；按「確認寫入尖峰明細」時**再跳一次確認框**，
  確認無誤才會以所選季度寫入。

  **不看固定欄位位置。** 各家報表的日期欄擺放都不一樣（實測看過
  上午!AB3、統計表 (1)!B2 這兩種），所以系統是把每張工作表最上面
  那一塊表頭文字整個讀過去找日期。有「日期：」「監測日期：」標示的
  優先，「製表日期」這類非調查日期會排除。

  ⚠️ **讀不到日期一律不阻擋匯入。** 只提醒「本次資料無法辨別日期，
  所以無法幫忙確認是否符合期別，請自行確認正確性」。

  新增的 surveyDateFromWorkbook() **完全獨立於 parsePeakSheet() 與
  matrix()**：它自己開活頁簿掃表頭前 12 列，不經過任何一條讀速率、
  延滯或 LOS 的路徑，所以不可能改到任何數值。

■ v2.20.14-2：期別顯示可以切成「實際調查月份」

  畫面右上角多一顆按鈕。平常顯示 115Q1，按一下改成這一季**實際做
  調查的月份**——2 月做兩條路段、3 月做三條的一季會顯示「115年2、3月」。
  尖峰明細、尖峰彙總、LOS 圖表與 Manager 比較表一起跟著換。

  都不含調查日期，覆蓋判斷完全不受影響；匯出的 Excel 內容一個字都沒變。

■ v2.20.9：獨立發現的方向文字備援不一致

  此項是在查證 Manager 舊專案包問題時另外重現的真實缺陷，
  但不是使用者當時看到舊名稱的成因。它的獨立情境是：

  ★ 那些路段其實**都沒有被命名過**。差別在於報告上有沒有寫
    「方向　往：本工西路--->岡山路」那一行。有寫的，系統匯入時會自動
    拿來當顯示名稱；沒寫的就沒有。所以看起來像「有些改到、有些沒改到」，
    實際上兩者都沒有人工命名過。

  ★ 而**尖峰明細一直都會退回那行報告文字，Manager 比較與尖峰彙總卻不會**。
    同一筆紀錄，在明細看得到「本工西路--->岡山路」，到了 Manager 變成裸的
    「方向1」。這是同一筆紀錄在兩個畫面顯示不同的一致性缺陷。

  改法：全站的方向名稱解析收斂成**同一支** displayDirectionName()，順序是

      專案包裡取過的名字 → 本機取過的名字 → 報告上的「方向往」文字 → 方向1／方向2

  Manager 比較、尖峰彙總、路段速限、健康檢查、速限版本清單、資料維護
  全部改走它。原本就有備援的尖峰明細行為不變。

  ⚠️ 報告上真的沒寫方向往的路段，仍然老實顯示「方向1／方向2」。
     系統不會憑空生一個名字——要有「北上／南下」這種正式名稱，
     還是要到「路段管理 → 方向顯示名稱」自己取一次。
     本版讓您在「路段速限」那一頁也看得出哪個方向是哪一邊，取名字不用再猜。

  ⚠️ 沒有變更任何計算規則、判定門檻、匯入方式或操作方式。數字與 v2.20.8 相同。

  守門測試新增 3 項，**已實測會在 v2.20.8 下紅字 2 項**

■ v2.20.7：Manager 比較的方向名稱不會再一半新一半舊（使用者回報）

■ v2.20.4：手冊的版號與日期改為單一來源

  v2.20.3 的手冊封面戳記寫 2026-08-25、每一頁頁尾卻印 2026-08-24。
  內容都對，只是兩處日期不一致。

  成因：兩支手冊產生程式各自把版號與日期**寫死**，升版時以字串取代
  修改，只要有一處對不上就安靜地失敗——而日期沒有任何檢查在看，
  版號檢查照樣全綠。同一種錯誤在這一組系統已經犯過四次
  （姊妹系統連續三版的更新說明也是這樣完全沒進到手冊裡）。

  根治：新增 manual-src/release.mjs，頁尾字樣與手冊檔名都由
  manual.html 封面戳記推導，兩者結構上不可能不一致。
  check-version.mjs 由 14 項增為 18 項，新增：找得到封面戳記、
  戳記版號等於 app.js 的版號、兩支產生程式裡沒有寫死的版號或日期。

  **已實測新檢查會失敗**：把寫死的日期塞回 build-pdf.mjs → 該項紅字；
  把封面戳記改成 v2.20.9 → 版號比對項紅字；還原後全部通過。
  （只加會通過的檢查等於沒加檢查。）

  網站本體只改版號字樣，app.js 的計算、門檻與畫面完全沒動。

■ v2.20.3：結論草稿的「條件範本」會跟著專案包走了

  範本只存在當下那一台電腦的瀏覽器裡，而「下載專案包」與
  「個人全部計畫包」都沒有把它收進去——在 A 電腦存了好幾組常用條件，
  帶到 B 電腦匯入之後一組都不會出現，畫面卻只說匯入成功。
  本版把 conclusionTemplates 一併收進兩種包，匯入時還原回去。

  只有備份檔實際帶著這個欄位時才覆蓋該計畫的範本；
  匯入舊版專案包不會把本機既有的範本清掉。
  升版前下載的舊包裡本來就沒有範本，請使用者重新下載一份。

  新增 backup-completeness.test.mjs（4 項）。

■ v2.20.2：Excel 解析多了一道邊界檢查

  本系統的 SheetJS 已經是官方 0.20.3（安全警示的修正版），
  這一版再加一層：解析時關掉用不到的公式、內嵌 HTML 與巨集；
  解析前後比對瀏覽器的內建物件，一旦某個檔案真的動到它，
  就當場中止這次匯入並指出是哪一個檔案，而不是安靜地繼續。
  即使日後元件版本被換回舊版，也不會無聲通過。

■ v2.20.2：備份包在 Windows 上更容易自行驗證

  測試用的瀏覽器尋找順序補上 Windows 的 Chrome 與 Edge、
  以及 macOS 與 Linux 的常見安裝位置——多數人是在自己的 Windows 電腦
  打開這個備份包，本機已經有瀏覽器時就不必再另外下載一份。


如何更新
-----------------------------------------------------------------
把本壓縮檔內的所有檔案，覆蓋到 GitHub repository
（https://github.com/baotoast/Travel-speed）的根目錄，然後 commit + push。
GitHub Pages 會自動重新發布，約 1～3 分鐘。

**請先手動刪除舊版檔案**（檔名帶版號，上傳不會自動刪掉舊的）：
  manuals 資料夾裡所有不是 v2.20.36 的
  交通服務水準分析系統_新手使用手冊_*.pdf 與 .docx；
  根目錄所有舊版 VALIDATION_v*.md，只保留 VALIDATION_v2.20.36.md；
  根目錄不可有過時的「給Claude的交接說明_v2.20.1.md」。

部署完成後請確認：左上角顯示「正式版 v2.20.36」，
「新手說明」頁的兩個下載連結點得下去（不是 404）。
