■ v2.20.15：日期檢查不再接受不存在的日期

  先前只檢查「1～12 月、1～31 日」，所以「115年2月29日」「115年4月31日」

    ・115年2月29日、115年4月31日 → 拒絕（視為讀不到日期）
    ・113年2月29日 → 正確辨識為 2024-02-29
  讀不到或無效的日期仍然只提醒、不阻擋匯入，行為沒有變。

  這一項來自「路口轉向」那一支的複查，因為 period-date 是三支程式的

■ v2.20.14-1：調查日期與季度對不對得起來

  選錯季度是最容易發生、也最難事後發現的一種錯——資料本身完全正常，
  只是被掛到錯的一季，之後的趨勢圖與歷季比較就整個歪掉。

  匯入前輸入的季度（例如 115Q1）與檔案表頭寫的調查日期如果對不起來，
  預覽上方會用**紅底**標出是哪幾份、檔案裡寫的是哪一天、屬於哪一季、
  來源是哪個工作表哪一格；按「確認寫入尖峰明細」時**再跳一次確認框**，
  確認無誤才會以所選季度寫入。

  **不看固定欄位位置。** 各家報表的日期欄擺放都不一樣（實測看過
  上午!AB3、統計表 (1)!B2 這兩種），所以系統是把每張工作表最上面
  那一塊表頭文字整個讀過去找日期。有「日期：」「監測日期：」標示的
  優先，「製表日期」這類非調查日期會排除。

  ⚠️ **讀不到日期一律不阻擋匯入。** 只提醒「本次資料無法辨別日期，
  所以無法幫忙確認是否符合期別，請自行確認正確性」。

  新增的 surveyDateFromWorkbook() **完全獨立於 parsePeakSheet() 與
  matrix()**：它自己開活頁簿掃表頭前 12 列，不經過任何一條讀速率、
  延滯或 LOS 的路徑，所以不可能改到任何數值。

■ v2.20.14-2：期別顯示可以切成「實際調查月份」

  畫面右上角多一顆按鈕。平常顯示 115Q1，按一下改成這一季**實際做
  調查的月份**——2 月做兩條路段、3 月做三條的一季會顯示「115年2、3月」。
  尖峰明細、尖峰彙總、LOS 圖表與 Manager 比較表一起跟著換。

  **只換顯示的文字。** 資料仍以 period 分組、排序與計算，id 與 rowKey
  都不含調查日期，覆蓋判斷完全不受影響；匯出的 Excel 內容一個字都沒變。

  ⚠️ **v2.20.15 以前匯入的資料沒有存調查日期**，那些季度照舊顯示季別；
  重新匯入原始檔之後就會有月份。

■ 三支程式共用同一份判斷

  判斷邏輯集中在新檔 period-date.js——路口轉向、全日交通量、
  交通服務水準**同一份程式、同一份測試表**。同一件事在三支各寫一套，
  就是漂移的開始。

■ v2.20.11：Manager 的搜尋框也吃得到方向顯示名稱了

  成因：那個名稱是從專案包的 roadMeta **即時解出來**的，
  而 roadMeta 掛在 packageRoadMeta 這個**物件**上。

  順帶的第二個症狀：正因為串進了兩個內部物件，
  **搜「object」會列出全部資料**。

  一併納入搜尋，並排除兩個內部物件。
  這是**多加一項**，不是改成「只搜畫面上的欄位」——
  站號、資料別這些沒印在表格上但一直搜得到的欄位，仍然搜得到。

  ★ 這和前幾版那一系列是同一族缺陷：**畫面顯示 X、功能操作 Y**。

■ v2.20.9-2：Manager 比較會告訴您「這份專案包已經不是最新的」

  ★ 這一項的緣由值得寫下來，因為它讓我們兩個各查了三輪。

  您回報「Manager 比較裡方向1/方向2 混雜著改好的名稱」，後來由**您自己實測釐清**：
  Manager 比較不會自動同步目前的 Project，
  必須先把 Project 匯出成專案包、再匯入 Manager，畫面才會更新。
  您重新匯出匯入之後，名稱就正確顯示了——程式其實一直是對的。

  這是刻意的分工：Manager 收的是**別人交來的一份交付**，不會因為對方後來
  又改了什麼就跟著變。但同一台電腦同時當 Project 又當 Manager 時
  （最常見的用法），這個分工會變成陷阱——畫面上原本**沒有任何線索**
  告訴您「您看的是幾月幾號匯入的那一份」。

      ⚠️ 11017 高捷岡山路竹RKC02標：本機內容較新

■ v2.20.9：獨立發現的方向文字備援不一致

  此項是在查證 Manager 舊專案包問題時另外重現的真實缺陷，
  但不是使用者當時看到舊名稱的成因。它的獨立情境是：

  ★ 那些路段其實**都沒有被命名過**。差別在於報告上有沒有寫
    「方向　往：本工西路--->岡山路」那一行。有寫的，系統匯入時會自動
    拿來當顯示名稱；沒寫的就沒有。所以看起來像「有些改到、有些沒改到」，
    實際上兩者都沒有人工命名過。

  ★ 而**尖峰明細一直都會退回那行報告文字，Manager 比較與尖峰彙總卻不會**。
    同一筆紀錄，在明細看得到「本工西路--->岡山路」，到了 Manager 變成裸的
    「方向1」。這是同一筆紀錄在兩個畫面顯示不同的一致性缺陷。

  改法：全站的方向名稱解析收斂成**同一支** displayDirectionName()，順序是

      專案包裡取過的名字 → 本機取過的名字 → 報告上的「方向往」文字 → 方向1／方向2

  Manager 比較、尖峰彙總、路段速限、健康檢查、速限版本清單、資料維護
  全部改走它。原本就有備援的尖峰明細行為不變。

  ⚠️ 報告上真的沒寫方向往的路段，仍然老實顯示「方向1／方向2」。
     系統不會憑空生一個名字——要有「北上／南下」這種正式名稱，
     還是要到「路段管理 → 方向顯示名稱」自己取一次。
     本版讓您在「路段速限」那一頁也看得出哪個方向是哪一邊，取名字不用再猜。

  ⚠️ 沒有變更任何計算規則、判定門檻、匯入方式或操作方式。數字與 v2.20.8 相同。

  守門測試新增 3 項，**已實測會在 v2.20.8 下紅字 2 項**
  （實際輸出 `有方向往的路段|方向1|方向1`，證明這個獨立缺陷在舊版存在）。
  第 3 項是回歸守門：報告沒寫方向往時不可以憑空生名字，新舊版都通過。

■ v2.20.7：Manager 比較的方向名稱不會再一半新一半舊（使用者回報）

  使用者回報：Manager 比較裡，同一個計畫有些路段顯示改好的方向名稱
  （南-北(北上)），有些還是「方向1／方向2」。

  成因：判斷「這個路段有沒有取過名字」時，只看「roadMeta 有沒有這筆項目」，
  沒有看「項目裡的名字是不是還是預設值」。而**設定路段有效期間時就會建立
  一筆項目**，內容是 {directionA:"方向1", directionB:"方向2", 起訖季度}
  ——那筆項目「有值」，於是擋掉了本機同一個計畫真正取好的名稱。
  所以是逐路段的：哪些路段設過有效期間，哪些就顯示不出來。

  改法：新增 hasRealDirectionName()，把「有沒有這筆項目」和「有沒有取過名字」
  分開；managerDirectionName() 改為「專案包 → 本機 → 鍵值」，挑真的有名字的那一份。

  ★ 使用者不需要重新匯出專案包，本版直接讀本機的設定。
  ★ 已實測：把本版的守門檢查放到 v2.20.6 的原始碼上會紅字，
     輸出 `示範路B(起~迄)|方向1|方向1`，與使用者截圖的症狀一致。

  範本只存在當下那一台電腦的瀏覽器裡，而「下載專案包」與
  「個人全部計畫包」都沒有把它收進去——在 A 電腦存了好幾組常用條件，
  帶到 B 電腦匯入之後一組都不會出現，畫面卻只說匯入成功。
  本版把 conclusionTemplates 一併收進兩種包，匯入時還原回去。

  只有備份檔實際帶著這個欄位時才覆蓋該計畫的範本；
  匯入舊版專案包不會把本機既有的範本清掉。
  升版前下載的舊包裡本來就沒有範本，請使用者重新下載一份。

  新增 backup-completeness.test.mjs（4 項）。

■ v2.20.2：Excel 解析多了一道邊界檢查

  本系統的 SheetJS 已經是官方 0.20.3（安全警示的修正版），
  這一版再加一層：解析時關掉用不到的公式、內嵌 HTML 與巨集；
  解析前後比對瀏覽器的內建物件，一旦某個檔案真的動到它，
  就當場中止這次匯入並指出是哪一個檔案，而不是安靜地繼續。
  即使日後元件版本被換回舊版，也不會無聲通過。

■ v2.20.2：備份包在 Windows 上更容易自行驗證

  測試用的瀏覽器尋找順序補上 Windows 的 Chrome 與 Edge、
  以及 macOS 與 Linux 的常見安裝位置——多數人是在自己的 Windows 電腦
  打開這個備份包，本機已經有瀏覽器時就不必再另外下載一份。


如何更新
-----------------------------------------------------------------
把本壓縮檔內的所有檔案，覆蓋到 GitHub repository
（https://github.com/baotoast/Travel-speed）的根目錄，然後 commit + push。
GitHub Pages 會自動重新發布，約 1～3 分鐘。

**請先手動刪除舊版檔案**（檔名帶版號，上傳不會自動刪掉舊的）：
  manuals 資料夾裡所有不是 v2.20.13 的
  交通服務水準分析系統_新手使用手冊_*.pdf 與 .docx；
  根目錄所有舊版 VALIDATION_v*.md，只保留 VALIDATION_v2.20.13.md；
  根目錄不可有過時的「給Claude的交接說明_v2.20.1.md」。

部署完成後請確認：左上角顯示「正式版 v2.20.13」，
「新手說明」頁的兩個下載連結點得下去（不是 404）。
