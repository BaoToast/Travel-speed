# 交通服務水準分析系統－GitHub Pages 發布說明

## v2.4 更新

- 「路段管理」新增開始／停止調查季度；健康檢查只要求有效期間內的路段資料。
- 匯入預覽新增「完全相符、別名相符、疑似相符、新路段」辨識狀態。
- 「資料維護」新增計畫資料品質總覽，集中顯示缺少平假日、缺少尖峰方向、速限未確認與歷季異常變化。
- 速限必須按「套用並重算」後才標記為人工確認；設定會隨 Project 備份包保存。

## v2.3 更新

- 新增「路段管理」頁面，可集中修改正式名稱與方向A／方向B顯示名稱。
- 支援檔名別名，例如「中正路」自動對應至「中正一路」。
- 合併重複路段前會顯示影響季度、尖峰明細、彙總及重複筆數，確認前自動下載備份。
- 匯入名稱正規化擴充至全形英數、括號、空白、波浪號、破折號、斜線及常見標點。
- 相同正規化簽章且只有一個候選路段時會自動對應；不確定時仍要求人工確認。

## v2.2 更新

- 「尖峰彙總」新增服務水準判定說明。
- 預設門檻已與 Excel 版統一：A ≥ 0.80、B 0.60～未滿0.80、C 0.50～未滿0.60、D 0.40～未滿0.50、E 0.20～未滿0.40、F 未滿0.20。
- A～E 最低速限比可按計畫分別調整；套用後自動重算尖峰明細、彙總與圖表。
- 自訂門檻會隨 Project 專案包及個人全部計畫包備份、還原。

## 發布步驟

1. 在 GitHub 建立新的儲存庫。
2. 將本資料夾內全部檔案上傳到儲存庫根目錄，包含 `.nojekyll`。
3. 進入儲存庫的 `Settings` → `Pages`。
4. 在 `Build and deployment` 選擇 `Deploy from a branch`。
5. Branch 選擇 `main`，資料夾選擇 `/ (root)`，再按 `Save`。
6. 等待 GitHub 完成發布後，按 `Visit site` 開啟正式網址。

## 重要資料說明

- 網站資料儲存在每台電腦自己的瀏覽器，不會上傳到 GitHub。
- 不同電腦需透過 Project 專案包匯出與匯入交換資料。
- 關閉瀏覽器不會清除資料，但清除網站資料、使用無痕模式、換瀏覽器或換網址會看不到原資料。
- 每完成一季應下載 Project 專案包備份。
- 請勿把原始調查 Excel、Project 專案包或其他正式資料上傳至公開 GitHub 儲存庫。

## 更新網站

日後取得新版網站檔案時，以新版 `index.html`、`styles.css`、`app.js`、`excel-export.js` 覆蓋儲存庫中的同名檔案即可。只要正式網址未改變，更新網頁通常不會清除瀏覽器中的既有資料。
