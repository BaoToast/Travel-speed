# 交通服務水準分析系統－GitHub Pages 發布說明

## v2.20.3 結論草稿的條件範本納入備份範圍

- 未變更任何服務水準門檻、代表紀錄選取、總延滯計算或操作功能。
- `projectPackage()` 與「個人全部計畫包」補上 `conclusionTemplates`；
  匯入專案包時把該計畫的條件範本寫回 `state.conclusionTemplates[計畫代碼]`。
- 只有備份檔實際帶著 `conclusionTemplates` 陣列時才覆蓋，避免匯入舊版包時
  把本機既有的範本抹成 `undefined`。
- 新增 `backup-completeness.test.mjs`（4 項）：以清單比對確認匯出／匯入
  兩端都收齊使用者自訂的設定，日後新增設定卻忘了收進備份會在這裡失敗。

## v2.20.2 Excel 解析的邊界防護

- 未變更任何服務水準門檻、代表紀錄選取、總延滯計算或操作功能；畫面行為與 v2.20.1 相同。
- Excel 解析加上一道邊界檢查：解析時關閉未使用的公式、內嵌 HTML 與 VBA 巨集解析路徑；
  解析前後比對 `Object.prototype` 的自有屬性，一旦來源檔案實際修改了內建物件，
  即中止該次匯入並指出檔名，而非安靜地繼續。即使日後 SheetJS 被換回舊版也不會無聲通過。
- 測試用瀏覽器的尋找順序補上 Windows 的 Chrome／Edge 與 macOS、Linux 的常見安裝位置，
  並固定以 UTF-8 地區設定啟動（精簡容器的空白 LANG 會讓下載檔名的中文字元被濾掉）。
- 新增 `xlsx-hardening.test.mjs`（4 項），從 `app.js` 直接取出實際執行的函式測試，
  不另抄一份；同時釘住「匯入真的走這一組安全解析選項」。

## v2.7 更新

### 修正：匯出的 Excel 圖表會讓 Excel 要求「修復」，修復後圖表全部消失

- 「LOS 圖表」頁下載的可編輯圖表檔（旅行速率趨勢圖、LOS 趨勢圖），內部的圖表 XML 有四處欄位順序不符合 ECMA-376（Excel 的檔案規格）：
  1. 數值軸把 `<c:majorGridlines>`（格線）排在 `<c:numFmt>` 之後，規格要求它必須排在 `<c:axPos>` 之後、`<c:title>` 之前。
  2. LOS 圖把 `<c:majorUnit>`（刻度單位）插在 `<c:majorGridlines>` 前面，規格要求它排在 `<c:crossBetween>` 之後，結果整個數值軸的順序連鎖出錯。
  3. LOS 圖的座標軸範圍寫成 `<c:min>` 在前、`<c:max>` 在後，規格要求 max 在前。
  4. LOS 圖由折線圖改成長條圖時，`<c:gapWidth>` 被接在結尾（`<c:axId>` 之後），規格要求它排在 `<c:axId>` 之前。
- Excel 開檔時會逐一驗證這些 part，任一處不合規就判定檔案毀損、跳出「我們發現…部分內容有問題。您要我們盡可能嘗試復原嗎？」；按「是」之後 Excel 會直接丟掉整張圖表，因此使用者看到的是「只有數字、沒有圖」。LibreOffice 較寬鬆，能開起來不代表 Excel 能開。
- 四處全部修正，並新增自動檢查（`ooxml-check.mjs`），往後每次改版都會驗證匯出檔的結構、`[Content_Types].xml` 覆蓋率與 relationship 對應是否完整。修正後圖表可直接開啟並保持可編輯。

## v2.6 更新

### 新增功能

- **可以刪除整個計畫**。「計畫設定」新增「刪除計畫」按鈕，刪除前會自動下載一份專案包備份，並一併清除該計畫的明細、彙總、速限、別名、路段設定與報告草稿，其他計畫不受影響。「備份與淨空」另提供「清除這台電腦上的全部計畫」（需連續確認兩次）。舊版只能刪除單一季度，而「建立全新空白模板」的說明文字與實際行為不符，一併修正。
- **成果交付的成果範圍可以跨季度**。改成「起始季度」與「結束季度」兩個下拉，可一次交付 114Q1～114Q4；起訖選反會自動對調，下方即時顯示涵蓋幾個季度。ZIP 檔名與內部各檔案都以完整範圍命名。
- **新手使用手冊**。以「完全不懂交通調查、也沒用過本系統」的使用者為對象，逐步帶完建立計畫、匯入、核對速限、判讀服務水準、修正資料、成果交付與備份，共 17 章、12 頁，另附常見問題與每季檢查表。網站「新手說明」頁可下載 PDF 與可編輯 Word。
- **改為離線可用**。Excel 讀取與壓縮元件改為隨網站一起提供，不再從外部網站載入。公司網路擋掉外部來源時，匯入與匯出仍可正常運作。

### 修正（全面檢查）

**Excel 讀取**

- 標題含有數字時會被誤讀成數值。例如「方向1平均總旅行速率：」會讀成 1、「平均總旅行速率（07:30~08:30）」會讀成 7，整份資料的服務水準全部變成 F 卻毫無警告。現在只有「冒號後面緊接著數字」才視為標題自帶數值。
- 行駛速率可能抓到隔壁方向的值。距離相同時改為優先取下方的標籤。
- 延滯只在「該方向自己的區塊」內尋找，不再抓到上一個方向的延滯表而讓兩個方向拿到相同數字。
- 總延滯缺少其中一項時，改為判定讀取失敗，不再把缺的那一項當成 0（舊版會嚴重低估總延滯卻照樣通過檢核）。
- 一張工作表若不是剛好兩個方向區塊（例如另有一個雙向平均區塊），改為明確報錯，不再用位置猜測而漏掉真正最差的方向。

**資料安全**

- 載入格式不對的備份檔時，原有資料不再被破壞。舊版會邊解析邊改資料，出錯後只顯示「這不是有效的備份檔」，實際上原本的計畫已被覆蓋且無法復原。
- 預覽之後若改了民國年或季度，預覽會自動失效並提醒重新預覽，不會再發生「寫進舊季度、紀錄卻寫新季度」。
- 同一批次內若有兩份檔案被判定為同一路段＋日別（會互相覆蓋），會列出檔名並擋下。
- 切換計畫、刪除計畫或清除全部資料時，未寫入的預覽會一併清空，不會寫到別的計畫。
- 民國年限定為 90～200 的整數，打錯不會再產生清不掉的幽靈季度。
- 計畫編號不得包含「|」符號（會導致刪除計畫時波及其他計畫的設定）。
- 匯入紀錄的復原新增保護：資料已被改名、合併或重新匯入時會擋下並提示改用備份還原，不會再把改名前的舊路段整批復活。
- 存檔失敗（無痕模式、儲存空間不足）會明確提示，不再靜默失敗。
- 匯入的專案包內容一律逸出後才顯示，避免夾帶指令碼。

**計算與設定**

- 刪除速限版本後，受影響的季度會正確退回基本速限並重算，不再停留在已刪除版本的速限。
- 路段改名或合併時，速限版本（有效期間、查證來源與人員）會一併搬移，不再變成孤兒而讓速限悄悄退回預設值。
- 速率缺值時速限比不再被算成 0（會被誤判為 F 並成為代表紀錄）。
- 自訂的服務水準門檻若剛好等於舊版預設值，不再於每次載入時被清掉。
- 期間排序一律依實際先後，民國 99 年與 100 年的資料不會再排反。
- 明細 CSV 的欄位改取所有列的聯集，不會因為第一列是舊版資料而漏掉來源欄位。
- 報告文字草稿不再被其他操作自動覆蓋；成果範圍也不會跨計畫沿用。

以上修正不改變既有的服務水準門檻、代表紀錄選取規則與總延滯計算方式。

## 發布步驟

1. 在 GitHub 建立新的儲存庫。
2. 將本資料夾內全部檔案上傳到儲存庫根目錄，包含 `.nojekyll`。
3. 進入儲存庫的 `Settings` → `Pages`。
4. 在 `Build and deployment` 選擇 `Deploy from a branch`。
5. Branch 選擇 `main`，資料夾選擇 `/ (root)`，再按 `Save`。
6. 等待 GitHub 完成發布後，按 `Visit site` 開啟正式網址。

## 重要資料說明

- 網站資料儲存在每台電腦自己的瀏覽器，不會上傳到 GitHub。
- 不同電腦需透過 Project 專案包匯出與匯入交換資料。
- 關閉瀏覽器不會清除資料，但清除網站資料、使用無痕模式、換瀏覽器或換網址會看不到原資料。
- 每完成一季應下載 Project 專案包備份。
- 請勿把原始調查 Excel、Project 專案包或其他正式資料上傳至公開 GitHub 儲存庫。
